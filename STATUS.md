# Smart Display - Status

## Project

Kitchen Smart Display covers two surfaces for the family: a Raspberry Pi kitchen wall display (React web app in `code/`) showing Today (weather, school schedule, morning departure timer), a Photos slideshow (Immich family photos plus a curated art collection), Music/Now Playing (Sonos transport with a Jukebox station picker), and full Settings; and a native SwiftUI Apple TV / Frame TV app (`tvos/`) mirroring similar views with a "Framed" art presentation for the living room.

## Stage

Active Development. Five screens are registered: the kitchen Pi, the Living Room Apple TV, and (as of 2026-09-24, pending Justin's first tap on the device) three Echo Shows (the family-room Echo Show 10, an Echo Show 15 in landscape, and the office Echo Show 5) running the kitchen web app in Silk. All of them depend on one hub, FrameServer on the NUC, and nothing else on the LAN.

## Recurring Tasks

The repeatable maintenance workflows (not one-off backlog items).

### 1. Add new photos from Google Photos

How we ran it 2026-06-09 (the 2018 album): you export, Claude does the rest.

1. **You:** export from Google Photos via Takeout and unzip into `~/Downloads/Takeout/` (ends up as `Google Photos <MM-DD-YYYY>/` with the album folders + `.json` sidecars inside).
2. **You:** tell Claude "I downloaded another album, add it to Immich" and paste the `immich-go-import` API key from 1Password when asked.
3. **Claude:** finds the new Takeout folder, dry-runs immich-go (binary: `~/Downloads/immich-go`, server `http://192.168.6.128:2283`), runs the real upload, waits for Immich's thumbnail + metadata jobs to drain (refreshing too early only picks up part of the import, caveat in `docs/designs/photo-refresh-automation.md`), triggers the Pi photo refresh, and verifies the new album landed in the manifest.

Kitchen + TV update within ~5 min of the rebuild. If Claude isn't around for steps 2-3, the manual command lives in the import log (`archive/import-log-2026-06-08.md`) and the nightly 3am refresh will pick up any finished import on its own.

### 2. Add art to the collection

The art collection lives as a single full-res copy in the NAS `Art/` folder, indexed in place by an Immich external library ("Art (NAS)"), organized into four movement-based `Art - <movement>` albums (full design: `docs/designs/art-collection-lifecycle.md`; acquisition + naming + tone: `docs/designs/art-metadata-style-guide.md`). Flow: Claude acquires into `_inbox/art-downloads/` (`dezoomify-rs` for Google Arts & Culture, Wikimedia for public-domain originals), names them `Title - Artist Year.ext`, and builds a review contact sheet in `_review/art-review.html`. You review/cull and assign the movement (exported to `_inbox/art-decisions.json`); then approved files drop into `Art/Art - <movement>/`, the Immich external library scans them in (auto or on demand), Claude curates `art-metadata.json` (`scripts/art-metadata-check.mjs` -> fill missing title/artist/year/movement + optional `rights` + fun facts), and a photo refresh lands it on both screens. Family photos still use the separate `immich-go` managed import. Rendering/schema detail: `docs/designs/art-albums.md`.

### 3. Triage place corrections

Wrong captions get long-press-flagged on the kitchen display and queue up on the Pi. Periodically (when the queue has a few): tell Claude "let's triage place corrections", that runs `flags-review.mjs` (self-serve review page in `_review/`), you fill in correct labels and export to `_inbox/`, then `flags-apply.mjs` writes the bubbles into `custom-places.json`. Finish with the printed commands: scp `custom-places.json` to the Pi, trigger a photo refresh, resolve the flags. Full flow: `docs/designs/photo-corrections-workflow.md`.

## Decisions Log

Append-only, newest first. Locked product decisions also live in `PRD - Smart Displays.md` ("Decisions Made") and `docs/Apple-TV-Display-PRD.md`; this log captures decisions made during working sessions.

- **2026-08-16 - The hub lives on the NUC, not the NAS. Superseded the 2026-06-09 decision.** House architecture is **NUC = applications, NAS = data**, and the display hub follows it. The earlier decision named the Synology as the eventual build host on co-location grounds (Immich lives there); that argument turned out to be weak, because originals are fetched once per asset and then reused by filename, so the LAN round trip is a one-time cost rather than a recurring one. ## Lessons

- **Edit the real render, not a picture of it (2026-09-24).** A WYSIWYG editor for a kiosk layout is cheap when the editor embeds the actual app in an iframe sized to the device's resolution and scaled with a CSS transform: viewport units resolve against the iframe, so fonts, panels and data are pixel-identical to the device, and the editor only draws handles from rectangles the app reports over postMessage. No second renderer to keep in sync. The preview must be a strict reader (no registration, no settings writes, no last-seen stamp) or the editor becomes a ghost screen on the dashboard.

- **A Google service account is the frictionless way to read a personal calendar server-side (2026-09-24).** No OAuth consent screen, no app verification, no weekly refresh-token expiry (the trap that ruled out the Photos APIs in May): create the service account, download its JSON key, share each calendar with its email address, and sign a JWT with Node's built-in crypto for a one-hour token. Contact birthdays live in Google's special calendar that cannot be shared this way; yearly events on an owned calendar can.
- **Keep secrets out of a Dropbox-synced inbox (2026-09-24).** `_inbox/` is gitignored but the project folder syncs to Dropbox, so a dropped private key is on every device. Move keys to `~/.config/<project>/` (mode 600) and to the server's `secrets/` folder by scp, then delete the inbox copy.

- **One uncaught error in an async Node request handler kills the whole process (2026-09-24).** FrameServer's handler was `async` and threw on a malformed percent-escape in a URL (`decodeURIComponent`), which became an unhandled rejection, and Node's default for those is exit. nssm restarted it each time, so it looked like flakiness rather than a crash. Wrap the handler (`handle(req, res).catch(...)`) and answer 500 for that one request; the fix is three lines and the failure is invisible until someone types a bad URL.
- **nssm 2.24's `AppRotateOnline=1` can wedge a service in Stop Pending (2026-09-24).** Rotating the log while the process runs left `SmartDisplaySonosAPI` unstoppable after node had already exited. Leave it at 0 (rotate on start only) unless the log is genuinely busy.
- **Silk on Fire OS cannot resolve mDNS, and neither will the eero's DNS answer for `.local` (2026-09-24).** Anything a Fire OS device must reach needs an IP with a DHCP reservation, and the app should treat "whoever served this page" as its API origin (FrameServer injects a `<meta name="smart-display-hub" content="self">` marker into `index.html` at serve time) so the same bundle works from an IP, a name, or a dev server.
- **Media retry loops need a backoff and a single pending timer (2026-09-24).** Every failed `<audio>` load fires `pause`; a resume scheduled per `pause` event stacks, and a page whose server went away hammered it several times a second, growing. Dedupe the pending resume and back off after `error`; let one watchdog own the retry.
- **Browser caches belong to the origin, identities to the URL (2026-09-24).** A settings cache in `localStorage` outlived a `?device=` switch on the same origin and seeded the new device's registry entry with the old device's per-screen values. Tag the cache with the id that wrote it and keep only house-wide keys on a mismatch. Same family as the tvOS simulator lesson below.
- **A hub-served page with no identity must not become the kitchen (2026-09-24).** The old default device id was `kitchen`; a laptop opening `http://nuc.local:8095/` would have adopted the kitchen's registry entry and any setting touched there would have changed the kitchen panel. Hub-served pages with no `?device=` or `?kiosk=` now register as `web-guest` (seeded from the kitchen, so it looks right).

- **A poll that republishes identical data is not free (2026-08-24).** A 10s settings poll deep-merged its response every tick whether or not anything had changed, handing every consumer fresh object and array identities six times a minute. Anything keyed on those identities restarts - here a `setInterval` rebuilt on each poll, so a 5-minute photo duration could never elapse and the kitchen slideshow froze on one image. The bug is invisible until someone picks an interval longer than the poll period. Two habits fall out: compare before publishing in any polling store, and never let a timer's lifetime depend on a callback identity that churns. (promoted to Build Guide v10.0, 2026-08-27)

- **Windows active hours protect the wrong window by default (2026-08-18).** "Active hours" is when Windows will NOT auto-restart; the unprotected remainder is when it will. A machine found at 13:00-07:00 active had its restart window at **07:00-13:00** - school mornings and midday - which is the worst slot for anything a household depends on. Windows 11 caps active hours at 18 hours, so you cannot protect the whole day; you are choosing which 6 hours are sacrificial, and it should be overnight. Check the actual values rather than assuming the default is sane. (promoted to Build Guide v9.4, 2026-08-18)

- **Windows reserves service names you would plausibly pick (2026-08-16).** `nssm install FrameServer` failed with "The specified service already exists" - `FrameServer` is the built-in **Windows Camera Frame Server**. Worse, the follow-up `nssm start FrameServer` started *Microsoft's* service. Check `Get-Service -Name <name>` before naming anything, and qualify app service names (`SmartDisplayFrameServer`) while keeping the bare product name for the display name and install directory. (promoted to Build Guide v9.3, 2026-08-16)
- **UNC paths do not authenticate from a non-interactive Windows session (2026-08-16).** Mapped drives like `Z:` are per-logon, which is well known - but even the raw UNC `\\HOST\Share` failed over SSH while working fine in the interactive desktop session. Anything running as a service needs machine-scope stored credentials (`cmdkey`), or the design should avoid the share entirely. Test from the *actual* non-interactive context before depending on it. (promoted to Build Guide v9.3, 2026-08-16)
- **PowerShell `Select-Object -First N` kills the upstream pipeline (2026-08-16).** Piping a long-running native command into it terminates the process once N objects arrive - a 30-second build "failed" in 0.8s with exit -1 and no error. Capture to a variable first (`$out = & cmd 2>&1`), then slice. (promoted to Build Guide v9.3, 2026-08-16)
- **Send PowerShell over SSH as `-EncodedCommand` (2026-08-16).** Multi-layer quoting (bash to ssh to PowerShell) mangles `$_`, quotes, and format operators. `printf '%s' "$PS" | iconv -f UTF-8 -t UTF-16LE | base64` then `powershell -NoProfile -EncodedCommand <b64>` passes arbitrary scripts through intact. (promoted to Build Guide v9.3, 2026-08-16)
- **Verify a new hostname's SSH key against an already-trusted address (2026-08-16).** Scripted `scp` under `BatchMode=yes` refuses an unknown host. Rather than `StrictHostKeyChecking=no`, compare `ssh-keyscan newname` fingerprints against `ssh-keygen -F <known-ip>`; identical keys prove it is the same machine, so adding it is safe rather than blind. (promoted to Build Guide v9.3, 2026-08-16)
- **Headless AI upscaling via Upscayl's bundled CLI (2026-08-13).** If Upscayl.app is installed, `/Applications/Upscayl.app/Contents/Resources/bin/upscayl-bin -i in.jpg -o out.png -m /Applications/Upscayl.app/Contents/Resources/models -n remacri-4x -s 4` runs Real-ESRGAN from a script with no GUI and no extra installs (~40-90s per image on this Mac). The `remacri-4x` model preserved painterly texture well; downscale the 4x output to the target size with `sips -Z`. Verified on 38 images. (promoted to Build Guide v9.1, 2026-08-14)
- **Squarespace sites expose full gallery data as JSON (2026-08-13).** Append `?format=json` to any Squarespace gallery page URL to get every item's title, date, and `assetUrl` without HTML scraping. The image CDN caps delivery at a 2500px long edge; `?format=original` does not bypass it. Default curl is blocked; send a browser User-Agent. (promoted to Build Guide v9.1, 2026-08-14)

- **A CORS allowlist must name every method the client uses, and an optimistic, silent store will hide it when it does not.** FrameServer allowed `GET, POST, OPTIONS`; the screens PATCHed; every browser-side settings write failed preflight and the next poll reverted it, invisibly, for weeks. Native clients (the tvOS app) do not hit CORS, so "the TV saves fine" proved nothing. Verify a write round-trips from a real browser origin, and log a failed write somewhere a human sees it.
- **Overnight builds: lead writes the contract, workers build against it in parallel.** Fixed the data shape, the theme tokens and the shared chrome first, then ran three panel/data workers and three composition workers concurrently with file-disjoint ownership and a lint+isolated-build gate. Each worker's report listed deviations, which is where the design calls surfaced.
- **Headless Chrome via `puppeteer-core` against the installed Chrome is a zero-download screenshot harness** at exact panel resolutions (1920x1080, 1280x800), and pinning a throwaway `?device=` id keeps dev writes off the production device record.
- **React Compiler lint rules change how you write React:** no `Date.now()`/`Math.random()` in render (seed the shuffle), no `ref.current` reads in render, no `setState` at the top of an effect, and an object literal with a key named `current` gets mis-flagged as a ref. Container-query-sized panels need definite grid tracks or the type collapses.

- **Blender MCP vs headless (2026-09-23).** The interactive Blender MCP server accepted connections but every request timed out; running Blender as `Blender -b file.blend --python script.py` was reliable, reproducible and parallelisable, so the whole Mixtape asset pipeline is CLI scripts with the MCP as an optional viewer. Default to headless for any Blender work driven by agents.
- **Options sheets for taste decisions.** A render matrix plus a self-contained HTML sheet with a copy-to-clipboard picks form is a cheap way to keep look-and-feel decisions with Justin while agents do the production work.
- **Camera projection beats rendering when a photoreal still exists (2026-09-24).** Project the photo onto crude 3D proxies with camera-baked UVs (not a per-frame UV Project modifier, which slides pixels); animate the proxies; inpaint only what the photo never saw. The still matched the source to under 1 level. A day of Blender look-dev could not approach what one generated image plus this technique gave.
- **Generated variants need per-item measured geometry.** Masked image edits place objects convincingly but drift 1 to 10 px per generation; measure each result (OpenCV circle and rect fits) and carry the numbers per item rather than fighting the model with tolerances it cannot meet.
- **Xcode 27 ships without the Metal Toolchain**; any target with a .metal file needs `xcodebuild -downloadComponent MetalToolchain` once (840 MB).
- **tvOS simulator pulls the real device's hub settings.** A per-device settings hub means a simulator running with a real device id silently adopts (and can write back) that device's config; give simulators a `debug.noHubSync` style flag.
